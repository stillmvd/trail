# Contract: запрос к модели отбора

Один POST на прогон: `https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer <ключ OpenRouter>`,
тело `{ model, messages: [{ role: "user", content: <prompt> }] }` (как `rank()` в Cairn, `digest.mjs:206`).

## Prompt

Текст `rank()` Cairn (`digest.mjs:166–203`) **дословно**, с подстановками:

- `Его интересы:` — `digest_interests` построчно с `- `;
- `Не берёт:` — `digest_avoid` построчно с `- `;
- `максимум ${maxItems}` — `digest_max_items`.

Добавляется (после блока «Не берёт», до «Ниже N материалов»):

```text
Раньше брал (лайки):
- <заголовок>            ← до 15 последних реакций value=1, новые сверху
Раньше отклонял (дизлайки):
- <заголовок>            ← до 15 последних value=-1
Источники, которые подряд отклонял — бери оттуда только очень сильное:
- <источник>: <N> отклонений подряд   ← только N ≥ 3
```

Блоки без строк не выводятся. Список тем и второй эшелон — в конце, перед форматом ответа:

```text
Каждому пункту дай тему ровно из списка: <метка 1>, <метка 2>, …, Любопытное.
Отдельно перечисли до 8 материалов, которые почти взял, — без why.
```

Список тем `topicsFromInterests(digest_interests)`: каждая непустая строка интересов → метка = текст до первого `:`,
а без двоеточия — первые 3 слова; обрезка пробелов и до 24 символов; дубли убираются; «Любопытное» добавляется
последней всегда (если её нет среди меток). Порядок групп в разделе = порядок этого списка.
Пример на интересах Cairn: Фронтенд и TypeScript / AI и LLM / Инструменты для Claude Code / Новинки гаджетов /
Любопытное и необычное — последняя метка уже начинается с «Любопытное», отдельная не добавляется
(сравнение по первому слову без регистра).

Формат ответа заменяется на:

```text
Верни строго JSON без пояснений:
{"picks":[{"i":<номер>,"t":"<первые 4 слова заголовка дословно>","why":"<одна фраза>","topic":"<тема>"}],
 "near":[{"i":<номер>,"t":"<первые 4 слова заголовка дословно>"}]}
```

Список кандидатов — как в Cairn: `${i}. [${source}] ${title} — ${blurb}`.

## Response handling

1. `extractJson` (Cairn `digest.mjs:153`) — вырезать первый JSON-объект из ответа.
2. `resolvePicks` (`digest.mjs:233`) с `normalize` — для `picks` и `near`: если эхо `t` не совпало с
   заголовком кандидата `i`, искать кандидата по эху; не нашли — отбросить.
3. `why` → `trimVerdict` (`digest.mjs:254–260`, `VERDICT_TAIL`) — без изменений.
4. `topic` вне списка → последняя метка списка («Любопытное…»).
5. Повторы `i` между `picks` и `near` — оставить в `picks`.
6. `picks` обрезать до `maxItems` (лимит прогона), `near` — до 8.
7. Добор (сводка дня уже есть): кандидаты — только материалы, которых нет среди позиций сводки (дедуп по `url`
   уже отсекает виденные); `picks` дописываются в `main` с `position` после текущего максимума и `added_at` = сейчас;
   `near` сводки удаляется и заменяется `near` этого прогона; если `picks` не пуст и `viewed_at` не NULL —
   `viewed_at` = NULL.

Ошибки: нет ключа → сбор не начинается (`digest_last_error` = «Нет ключа OpenRouter»); HTTP ≠ 2xx или
невалидный JSON → сводка не создаётся, ошибка в `digest_last_error`, кандидаты остаются сохранёнными.
